# Дорожная карта StabCam

## Сделано
- Живая гиро-стабилизация (rolling shutter, адаптивный кроп, **точный расчёт «кадр не выходит за границы»**), шумоподавление по времени (+ пространственное и поиск смещения ±2 px), бикубика + резкость, LUT, HLG 10-бит.
- **Горизонт** (выравнивание крена по гравитации): живой режим ограничен запасом кропа, полный диапазон (±45°) в обработке ПОСТ.
- Режим ПОСТ: запись без обработки + лог гироскопа (`.gcsv`, Gyroflow) + лог гравитации + метаданные кадров; обработка на телефоне с предвидением, в **фоновой службе с очередью и уведомлением**.
- Моды `.module`, простой/«Про» режимы, окно обновления, надёжная проверка обновлений.

## Открыто: лаги стабилизации в 4K·60 с включённым OIS
Наблюдение пользователя (OnePlus 15R): иногда заметны «лаги» при STAB в 4K·60 с OIS. Камера 4K60 поддерживает (стоковое приложение снимает), но Camera2 не объявляет `3840×2160@60` в списке режимов для обычных приложений. Приложение всё равно просит 60 fps и получает их (по логу ровные 60 fps), поэтому причины ищем в другом:

| Гипотеза | Как проверяем | Что делаем |
|---|---|---|
| OIS и своя стабилизация «спорят»: OIS уже убрал часть дрожания, а гироскоп видит его целиком, и приложение компенсирует лишнее | Сравнить три ролика: OIS выкл / вкл / вкл + STAB (кнопка OIS, лог `Stab`) | Если OIS-вкл хуже: рекомендовать OIS выкл при STAB; экспериментальный масштаб высокочастотной части гироскопа (`stab.gyroHfScale`); поиск vendor-режима «только OIS» |
| Неровный интервал кадров / пропуски в режиме 4K60 | В логе каждые 2 с: `интервал ср/макс`, `пропусков` | Если пропуски: подбор режима датчика через vendor-ключи (`com.oplus.camera.mode`, `SensorModesInConfig`, `com.oplus.is.sdk.camera.package`) — лаборатория vendor-ключей теперь умеет строки и массивы |
| Нагрев и троттлинг | В логе `тепло N` (0–6 по `PowerManager`) | Адаптивное снижение нагрузки (отключить пространственный шумодав, затем бикубику) |
| Рассинхрон гироскопа и кадров | `stab.timeOffsetMs` ±10 мс, смотреть дрожание | Автоподбор по лог-записи (корреляция гироскоп ↔ движение кадра) |

Просим: снять 3 ролика (OIS выкл, OIS вкл, OIS вкл + STAB) и прислать строки `Stab` из лога.

## Нейросетевое шумоподавление (отложено, ждёт решения по модели)
Условия, чтобы начать:
1. **Модель.** Нужны веса image→image (шумодав), лицензия, допускающая использование в приложении (Apache-2.0/MIT/BSD), размер до ~10 МБ в int8. Проверенных подходящих TFLite-весов в открытых каталогах найти не удалось; нужен выбор конкретной модели (например, из NAFNet / FastDVDnet-семейства после конвертации) или обучение на своих данных.
2. **Среда.** LiteRT (`com.google.ai.edge.litert`) с GPU/NPU-делегатом, модель скачивается отдельным модулем (в APK не кладётся), только режим «Максимум» при обработке ПОСТ.
3. **Бюджет.** Прогон 20 с 4K60 через сеть кусками 512×512 ≈ 1–8 минут в зависимости от модели; поэтому только офлайн и по желанию.

Пока шумоподавление — классическое (C1): временное с компенсацией движения + пространственный билатеральный фильтр, вдвое сильнее в режиме обработки ПОСТ.

## Идеи на потом
- Автоопределение осей гироскопа по оптическому потоку.
- Нормализация OIS: оценка вклада OIS по расхождению «гироскоп ↔ движение кадра».
- Предпросмотр результата обработки ПОСТ на 5 секунд до полного прогона.
