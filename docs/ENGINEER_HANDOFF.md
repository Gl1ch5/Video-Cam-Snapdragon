# StabCam: документ для инженера (передача проекта)

Репозиторий: `Gl1ch5/Video-Cam-Snapdragon`. Ветка разработки: `ccr-b86a8234-yo5sd8`. Подробные правила и карта кода: `AGENTS.md`. Этот документ даёт общую картину, состояние и открытые вопросы.

## 1. Что это и зачем

Android-камера «только видео» с **собственной гиро-стабилизацией** в реальном времени (идея как у GoPro HyperSmooth/DJI RockSteady): шумоподавление, LUT, 10-бит HLG, обработка после съёмки (ПОСТ), моды `.module`, автообновление с GitHub. Целевое устройство: **OnePlus 15R (CPH2767, Snapdragon SM8845)**. Код рассчитан на любые Android 12+ с Camera2, но проверялся только на 15R.

Главная цель: стабилизация не хуже стоковой камеры при беге и ходьбе, 4K60/4K120, максимум качества картинки.

Разработка ведётся без доступа к устройству: пользователь тестирует сборки и присылает логи и скриншоты. **Всё, что завязано на GL, Camera2 и MediaCodec, проверяется только на телефоне.**

## 2. Состояние на сегодня

Проверено на устройстве (по логам пользователя): запись 4K60 HEVC 10-бит HLG и 8-бит, гироскоп ~467 Гц, оси `[-y,-x,-z]`, автообновление (через страницу релиза при 403 от API), калибровка осей и времени, диагностика OIS, превью и запись со STAB.

**Не проверено / открыто:**
- Качество стабилизации при ходьбе и беге. Пользователь оценил её как заметно хуже стока. Найден и исправлен баг (накопление крена горизонт-лока в состоянии `Stabilizer`); исправление **ещё не проверено на телефоне**.
- 4K120 (high-speed), режим ПОСТ и офлайн-обработка на устройстве.
- Просадки fps: при старте (совпадают с диагностикой стабилизации и автокалибровкой) и при записи 4K60 HLG (кадр 13–19 мс при бюджете 16,7 мс). Причина не доказана.
- Двойная компенсация OIS и гироскопа: камера принимает «OIS выкл», но в результате кадра OIS всегда «вкл(1)»; выключить его через Camera2 нельзя.
- Короткие клипы (~90 кадров): `Mp4Tagger` пишет «moov не в конце файла, метаданные пропущены».
- Все пресеты для Pixel, Samsung, Xiaomi не проверялись.

## 3. Архитектура

Подробно в `AGENTS.md`, коротко:

- **Живая запись:** Camera2 → `SurfaceTexture` (OES) → `StabPipeline` (поток GL, OpenGL ES 3.2) → шумодав по времени → warp по строкам (rolling shutter) + бикубика (Catmull-Rom) + CAS-резкость + LUT → окно превью и энкодер (`StabRecorder`: MediaCodec HEVC + AAC + MediaMuxer). 10-бит HLG: буфер RGB10_A2 и `EGL_GL_COLORSPACE_BT2020_HLG_EXT`.
- **ПОСТ:** запись без обработки + `.gcsv` (формат Gyroflow) + `.grav.csv` + `.meta.json` (время, выдержка, ISO кадров). `OfflineProcessor` (в `ProcessingService`): траектория целиком, гауссово сглаживание в обе стороны (предвидение), декодер → GL → энкодер, звук копируется.
- **Конфиг (поздний побеждает):** `default.json` → пресет устройства → включённые моды → пользовательский `config_user.json`.

Ключевые файлы (`app/src/main/java/com/gl1ch5/stabcam/`): `stab/StabPipeline.kt`, `stab/Stabilizer.kt`, `stab/FrameFit.kt`, `stab/Shaders.kt`, `stab/GyroTracker.kt`, `stab/AxisCalibrator.kt`, `stab/OfflineProcessor.kt`, `camera/VideoCamera.kt`, `camera/CameraCaps.kt`, `config/*`, `ui/MainActivity.kt`.

## 4. Алгоритмы стабилизации

1. **Гироскоп:** `GyroTracker`, 400 Гц, часы boottime (те же, что у меток кадров). Оси `["-y","-x","-z"]`; смещение времени `stab.timeOffsetMs`.
2. **Живое сглаживание (`Stabilizer`):** виртуальная камера движется с постоянной скоростью намеренного движения (фильтр `velTau`) и подтягивается к реальной ориентации с постоянной времени от `tauMax` (в центре) до `tauMin` (у границы запаса). Смещение жёстко ограничено запасом кропа.
3. **Точный запас кропа:** `FrameFit` проверяет углы и середины краёв кадра с отступом 1,5 %; кроп адаптивный (`minCrop` … `crop`): растёт при тряске, спадает в покое (аналог Auto Boost у GoPro).
4. **Rolling shutter:** `Stabilizer.ROWS = 16` матриц на кадр, интерполяция в шейдере (`uR[ROWS]`).
5. **Интринсики:** базовые из `CameraCaps`, по кадрам из `LENS_INTRINSIC_CALIBRATION` (с валидацией ±12 % по фокусу, ±5 % по центру, сглаживание EMA).
6. **Горизонт:** `HorizonLock` (гравитация, привязка к 90°). Крен применяется **только к выходному кадру**, в состоянии стабилизатора его нет (иначе накапливается; это и был исправленный баг).
7. **Шумодав:** пространственный билатеральный 3×3 + временная история, перепроецированная по гиро, с поиском сдвига ±2 px; сигма по ISO (`stab.denoiseAuto`), при сильном нагреве отключается.
8. **Режимы пользователя** (`Presets.strength`): Лёгкая (кроп 1,10), Стандарт (1,15), Ходьба / бег (1,30, до 12°), Максимум (1,40, до 15°). Нажатие на кнопку STAB открывает меню.
9. **Автокалибровка** (`AxisCalibrator`): подбор осей (24 собственных поворота) и сдвига времени по оптическому смещению против гиро.

## 5. Что уже решено и что отвергнуто

- Встроенный нейро-шумодав: NAFNet-SIDD width32 (MIT, 62,5 МБ) проверен, около 126 тайлов на кадр 4K — для видео неприменим (`docs/ROADMAP.md`).
- Подмена package name под вендорские whitelist: отклонено.
- Стоковый EIS по умолчанию вместе со STAB: нельзя (обрезает и мылит кадр).
- Значения vendor-ключа OnePlus `com.oplus.video.stabilization.mode` (0–3) принимаются, смысл неизвестен: не гадать, сравнивать на картинке.
- Принято из исследовательских отчётов: 16 строк warp, интринсики по кадрам, TNR по ISO, CAS, термодеградация, оценка сдвига времени гиро, ограничение выдержки (Android 15+, экспериментально), камерный NR «минимальный» в ПОСТ.

## 6. Что делать дальше (по приоритету)

1. **Проверить исправление горизонт-лока на улице.** Профиль «Прогулка» или режим «Ходьба / бег»; в логе `Stab` смотреть «поправка ср» и «кроп» (в покое должны быть около 0–1° и заметно меньше 1,2). Строка теперь содержит «горизонт X°».
2. Если стабилизация всё ещё хуже стока: сравнить три записи 4K60 (OIS выкл / вкл / вкл + STAB) по логам; проверить гипотезы двойной компенсации с OIS, запаса кропа при беге, синхронизации времени.
3. Убрать причины просадок fps: отложить диагностику стабилизации (пробы меняют запросы камеры) и автокалибровку; при записи 4K60 HLG попробовать рендерить превью через кадр.
4. Проверить 4K120, ПОСТ и офлайн-обработку.
5. Разобраться с пропуском метаданных для коротких клипов.
6. Рассмотреть учёт данных OIS (сдвиг линзы) в модели стабилизации, если Camera2 их отдаёт.

## 7. Сборка, тесты, CI

```bash
./gradlew assembleDebug assembleRelease testDebugUnitTest --no-daemon -q
```

JDK 17+, Android SDK (platform 36). Зависимости: Kotlin stdlib, без AndroidX. Юнит-тесты покрывают только чистую математику (кватернионы, сглаживание, `FrameFit`, горизонт, калибровка, `.gcsv`, конфиги, модули). Есть регрессионный тест `horizonRollDoesNotAccumulateInState` (старый код его проваливает).

CI: `build.yml` (тесты + debug APK), `nightly.yml` (release APK → pre-release `nightly` на GitHub, версия `0.1.0-nightly.ДАТА.SHA`). Подпись общим ключом `ci/stabcam-ci.jks` (пароль публичен, это не защита). Приложение само находит и ставит новые сборки.

## 8. Известные грабли (кратко; полный список в `AGENTS.md`, раздел 5)

- Android ICU: в регулярках `}` экранировать (`\\}`).
- Не использовать матрицу `SurfaceTexture`; вся математика в неповёрнутой сенсорной системе.
- Шейдеры компилируются только на устройстве; новый uniform добавлять в обоих путях (`StabPipeline` и `OfflineProcessor`).
- UI только на главном потоке; исключения на потоках GL/камеры логируются, а не роняют приложение; после падения включается безопасный режим.
- Порядок параметров конструктора `StabPipeline`: `denoiseAuto` последний.
- Релиз `nightly` пересоздаётся каждый раз; сравнение версий по имени APK; лимит GitHub API (403) обходится кэшем ETag и страницей релиза.

## 9. Как работать с пользователем

Пользователь русскоязычный и пишет коротко. Он тестирует на 15R и присылает логи (Настройки → Система → Лог) и скриншоты. После изменений в GL, Camera2 или MediaCodec всегда прямо писать, что на устройстве не проверено, и просить конкретный лог (строки `Stab`, `Probe`, `Gyro`). PR создавать только по просьбе; коммиты идут в ветку сессии.
